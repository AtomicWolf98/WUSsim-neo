# 模块建模：检测模型与 PHY 边界

## 1. 当前检测模型

本版本没有生成 OFDM 波形、信道、噪声、接收滤波或门限。`runner.py` 对每次 WUS/DCP occasion 生成独立均匀随机数，并按条件使用：

\[
\begin{aligned}
P(NO\_WAKE|H1)&=MDR,\\
P(WAKE|H0)&=FAR,\\
P(WAKE|H2)&=FDR.
\end{aligned}
\]

主配置设 `MDR=FAR=FDR=0.01`，证据等级为 `ASSUMPTION`。理想切片设三者为 0；受损切片设 `MDR=0.15`、`FAR=0.08`、`FDR=0.12`。

## 2. 三个比率必须分开

- MDR：H1 中未唤醒次数 / H1 总数；
- FAR：H0 中错误唤醒次数 / H0 总数；
- FDR：H2 中错误唤醒次数 / H2 总数。

若某一条件没有样本，相应比率为 `null`，不能填 0。单 UE 场景可能没有足够 H2 样本，因此 FDR 常不具备稳定估计意义。

## 3. 为什么它不是 PHY 仿真

真实检测性能至少依赖 SNR、信道模型、带宽/序列、同步误差、频偏、天线、接收机实现、干扰、覆盖点和阈值校准。当前 1% 是概率输入，不是由这些物理量计算的输出。因此本项目不能给出：

- BLER、检测曲线或覆盖增益；
- 某个 WUS 波形在某 SNR 的性能；
- 满足规范接收机要求的结论；
- MDR/FAR/FDR 在真实设备上的校准值。

## 4. 检测对节能的影响

误检会产生不必要唤醒，漏检会推迟业务到后续 occasion。64-seed 主配置下 Case 1-6 为正收益，但 8-seed 受损检测切片中：FTP3 仅 11.66%，95% 区间跨 0；IM 为 -68.01%。这说明检测不是结果表里的装饰参数，而是决定独立 WUS 是否成立的关键变量。

## 5. 面向 3GPP 讨论的表述

可以说：“在给定 MDR/FAR/FDR 假设下，协议级事件与能量账本产生如下结果，并对受损检测进行敏感性分析。”不能说：“仿真证明该 WUS PHY 达到 1% 检测错误率。”后者需要链路级模型和校准证据。
