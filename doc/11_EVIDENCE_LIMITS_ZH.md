## 2. 证据链

每个冻结配置项在 JSON 中保存 `source_id`、`locator`、`evidence_status` 和解释。会议定义、公司提案、研究参考和项目假设分开标记。manifest 记录 profile、配置和关键源码 SHA-256；结果目录记录自身 SHA-256。

Case 列表的会议地位不能自动提升 Case 内的数值。尤其是 5 ms period、8 ms timer、测量 160/2 ms、120/18 功耗和 10 ms 唤醒延迟来自公司文稿或组合假设，并非 Case 名称本身规定。

## 3. 当前可支持的讨论

- 单 UE、连接态 Case 1 机制在冻结假设下的相对功耗、时延和 PDB 比较；
- MR/LR 时间和转换能量的可审计账本；
- 同业务 seed 的配对统计和置信区间；
- timer、测量、检测、MO 时长、服务率、相位和 LR 功耗的敏感性；
- Case 1-5/1-6 高增益的反事实归因。

## 4. 当前不能支持的结论

- 3GPP 一致性、规范合规或会议已认可的节能百分比；
- 波形、接收机、SNR、BLER、覆盖或链路预算结论；
- 多 UE 调度、资源开销、gNB 能耗或网络节能；
- 绝对 mW、整机电池寿命和商用芯片实测结论；
- 完整 Rel-19 RRC/MAC/PHY 流程、邻区 RRM、VoIP/XR 或 Case 2；
- 把某家公司文稿参数推广为全行业统一参数。

## 5. 升级为文稿级数值证据仍需什么

至少需要：冻结的 3GPP 评估场景与多个公司可比较参数；链路级 MDR/FAR/FDR 曲线；目标 UE 的状态/转换实测或共同功耗模型；真实调度、BLER/HARQ 与控制开销；多 UE 资源和网络侧开销；更长时间/更多 seed 的收敛；跨实现复算。完成这些工作前，项目应保留“机制级、相对功耗、未校准”的限定。
