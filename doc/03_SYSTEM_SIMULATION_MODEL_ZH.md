# 系统级仿真建模

## 1. 一次 run 的处理链

```mermaid
flowchart LR
  A[冻结 profile/config] --> B[按 seed 生成业务]
  B --> C[构建 C-DRX/WUS/测量事件日历]
  C --> D[状态机产生监听、timer、睡眠动作]
  D --> E[FIFO 队列在可用窗口内传输]
  E --> F[合并 MR 活动并填充睡眠间隙]
  F --> G[积分 MR/LR 与增量能量]
  G --> H[包时延、PDB、完成率、检测指标]
  H --> I[同 seed 配对比较与 bootstrap]
```

所有公开时间使用整数 ns 和半开区间 `[start_ns, end_ns)`。同一 seed 的六个 Case 先生成完全相同的 Packet 列表，并要求 `traffic_sha256`、观察窗起止和窗口长度一致；任一项不一致就拒绝配对收益。

## 2. 时间窗

主矩阵先运行两个 C-DRX 周期作为预热，再统计固定观察窗，最后运行一个 PDB 的排空期。

| 业务 | 预热 | 观察窗 | 排空 | 计能范围 |
|---|---:|---:|---:|---|
| FTP3 | 320 ms | 320～960 ms，共 640 ms | 100 ms | 只计 320～960 ms |
| IM | 640 ms | 640～3840 ms，共 3200 ms | 300 ms | 只计 640～3840 ms |

排空期用于判断观察窗内到达的包能否完成，不向观察窗能量加账，也不加入新到达。这样避免窗口末端未完成包被误判为消失，同时避免用额外排空能量稀释平均功耗。

## 3. 因果顺序

包到达只进入 gNB/UE 抽象队列，不直接启动 UE inactivity timer。只有成功调度产生的 `NEW_TRANSMISSION` 才重启相应 timer。同一时刻按稳定事件优先级处理；WUS 监测开始时冻结本 occasion 的 H0/H1/H2 条件，之后到达的包不能反向改变已经开始的检测。

服务窗口内若一次传输未用完队列，继续按 FIFO 服务；每次真实新传都会把活动窗口延长到新的 timer 终点，并立即消费新增窗口。包可以分段，但同一包的成功 Tx 段必须时间连续、bit 区间不重叠、服务 bit 加剩余 bit 等于总 bit。

## 4. 系统能量方程

主接收机 MR 和低功耗接收机 LR 各自形成全窗口闭合、内部不重叠的区间。基础能量为：

\[
E_{interval}=\sum_i P_i\frac{t_{i,end}-t_{i,start}}{10^6}.
\]

转换和 EE 测量进入增量账本：

\[
E_{total}=E_{MR}+E_{LR}+E_{transition}+E_{EE},\qquad
\bar P=\frac{E_{total}}{T_{window}}.
\]

转换能量是额外能量；转换时间用于判断某个睡眠态是否可进入。两者不能互相替代，也不能既作为状态时长又重复计入额外功耗。

## 5. Case 比较

节能采用配对 seed 的总能量比：

\[
G_c=1-\frac{\sum_s E_{c,s}}{\sum_s E_{1-1,s}}.
\]

正值表示比 Case 1-1 省电，负值表示更耗电。程序不会把“1-5/1-6 必须最省电”写成 PASS 条件；PASS 只表示输入配对、区间闭合、能量重算、队列守恒和结果校验通过。

## 6. 系统模型边界

本项目没有多 UE 竞争、真实资源栅格、HARQ、MCS/BLER、波束扫描、信道估计、邻区 RRM、gNB 能耗或绝对电池模型。固定服务率和 Bernoulli 检测把这些链路细节压缩成显式假设。因此它可以支撑“机制与假设的技术讨论”，不能独立支撑覆盖、容量、网络节能或标准一致性结论。
